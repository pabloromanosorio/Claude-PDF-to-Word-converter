## CRITICAL: UNIVERSAL TABLE RECOGNITION

### Table Detection Rules (Pattern-Based):

**A section should be converted to a TABLE if it exhibits ANY of these patterns:**

1. **Structural Patterns:**
   - Content organized in consistent rows with 2+ columns
   - Vertical alignment of data across multiple rows
   - Repeated data structure (same fields/categories repeating)
   - Horizontal rules, borders, or visual separators between sections
   - Grid-like visual layout

2. **Content Patterns:**
   - Header row followed by multiple data rows with same structure
   - Data that can be categorized into distinct fields/attributes
   - Parallel information (same type of info repeated for different items)
   - Comparison data (multiple entities with same attributes)
   - Quantitative data with labels and values in columns

3. **Spacing/Alignment Indicators:**
   - Consistent column-like spacing using tabs or alignment
   - Multiple items with values aligned at same horizontal positions
   - Visual columns created by whitespace
   - Monospaced text used to create column alignment

4. **Semantic Indicators:**
   - List of items with multiple attributes each
   - Data that answers "what, when, where, how much" repeatedly
   - Catalog or inventory-style content
   - Comparative information across categories
   - Aggregated or summarized data with totals/subtotals

### Decision Framework:

**ASK THESE QUESTIONS:**

1. **Multi-Column Document Test:** Is this a multi-column document layout (like a newspaper)?
   - YES → Extract text left column FIRST (entire column), then right column BELOW as plain paragraphs. DO NOT use tables.
   - NO → Continue to next test

2. **Spatial Layout Test:** Is text positioned side-by-side that needs to STAY side-by-side (not sequential reading)?
   - Examples: Three signatures in a row, date on right + name on left at same height
   - YES → Create INVISIBLE-BORDERED table (BorderStyle.NONE) to preserve horizontal layout
   - NO → Continue to next test

3. **Column Test:** Does this content have 2+ distinct columns of DATA (not document layout)?
   - YES → Likely a data table (with visible borders)
   - NO → Continue to next test

4. **Repetition Test:** Does the same structure repeat for multiple items/rows?
   - YES → Likely a data table (with visible borders)
   - NO → Continue to next test

5. **Attribute Test:** Are multiple attributes being shown for each entity/item?
   - YES → Likely a data table (with visible borders)
   - NO → Continue to next test

6. **Comparison Test:** Is this comparing or listing similar items side-by-side?
   - YES → Likely a data table (with visible borders)
   - NO → Likely plain text

7. **Alignment Test:** Is vertical alignment critical to understanding the data?
   - YES → Definitely a data table (with visible borders)
   - NO → Could be plain text

**IF TEST 1 ANSWERS "YES" → Plain paragraphs (left column first, then right column below)**
**IF TEST 2 ANSWERS "YES" → CREATE INVISIBLE-BORDERED TABLE**
**IF 2+ OF TESTS 3-7 ANSWER "YES" → CREATE VISIBLE-BORDERED TABLE**

### Table vs. Plain Text Guidelines:

**CREATE AS TABLE when:**
- Information is in a grid/matrix format
- Column headers exist (explicitly or implicitly)
- Same categories repeat for different rows
- Alignment reveals relationships between data
- Content would lose meaning if column alignment were removed
- Data is structured for scanning/comparison

**KEEP AS PLAIN TEXT when:**
- Content flows narratively
- Information is hierarchical but not columnar (like addresses)
- Single-dimension lists (simple bullets/numbers)
- Paragraphs or prose
- Content is sequential rather than parallel

### Universal Table Structure Requirements:

**For ANY table you create:**

1. **Header Row:**
   - Identify or infer column names from content
   - Bold text, gray background (E7E6E6), **BLACK TEXT** (000000)
   - First row of table

2. **Data Rows:**
   - One entity/item per row
   - Consistent number of columns per row
   - Cell content matches column purpose
   - **ALL TEXT BLACK** (000000)

3. **Formatting:**
   - Thin borders (1pt, gray or black)
   - Consistent cell padding (50-180 DXA)
   - Appropriate column widths based on content length
   - Text alignment: left for text, right for numbers, center for headers

4. **Column Width Calculation:**
   - Total available width: ~9360 DXA (letter size with 1" margins)
   - Distribute based on content: wider for long text, narrower for codes/numbers
   - Example 3-column table: [3120, 3120, 3120]
   - Example 5-column table: [2000, 2000, 2000, 1500, 1860]
   - Adjust proportionally based on actual content needs
